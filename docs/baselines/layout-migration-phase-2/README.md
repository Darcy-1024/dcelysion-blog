## 实施范围

- `resolveSidebarLayout(input)` 是 SSR 与 Swup 共用的唯一纯布局计算入口。输入包含页面类型、侧栏开关与位置、文章页隐藏/临时双栏、特殊文章 TOC 布局、左右组件存在性和平板侧栏选择；输出包含有效状态及网格、左右栏、正文和页脚类。
- `getEffectiveSidebarState()` 只负责把站点配置归一化成纯函数输入；`MainGridLayout.astro` 直接渲染其输出，并把同一份配置摘要写入 `data-*`。
- `updateMainGridCols()` 只从稳定 DOM 读取配置摘要与 `#swup-container[data-page-kind]`，调用同一纯函数，再替换受管布局类。页面类型不再由 URL 字符串另行猜测。
- 保留 `#main-grid`、`#swup-container`、左右动态容器、侧栏 ID、DOM 顺序和现有 Swup 事件入口；没有迁移页脚、全面改 CSS 变量、引入新沉浸视觉或重构播放器。
- 所有 Tailwind 响应式类仍以完整静态字面量留在源码中；当前 `--page-width` / `siteConfig.pageWidth` 链路保持不变，为后续 CSS 变量阶段留下显式的纯计算输入/输出边界。

- 浏览器控制台仍出现既有 `SwupA11yPlugin: No main heading (main h1 / h1) found on new page` 警告；本阶段未改变文章页既有隐藏标题结构，也未把该无障碍问题扩展进布局迁移范围。
