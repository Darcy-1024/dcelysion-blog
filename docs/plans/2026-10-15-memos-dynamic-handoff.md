## 1. 已确定的目标与边界

- 直接使用原版 Memos 的写作、上传图片、编辑和管理界面，主要用于发博客动态。
- 博客动态与图片最终沿用原有存放和生成方式；不重做类似 Memos 的编辑器，不把博客前台改成直接读取 Memos。
- 原版 Memos 仍需要自己的数据库及附件存储。接受其作为编辑来源，博客 Markdown 和图片是发布副本；不是让 Memos 原生直接读写博客仓库。
- 保留历史动态、图片顺序、正文、标点、表情、发布时间、评论关联和前台展示。不同步历史内容回 Memos，不做双向同步。
- 不替换文章、相册、音乐、壁纸、Waline、Umami或整个现有后台，不迁移旧媒体。
- 本次仅授权制定计划和写交接文档，不授权安装服务、生产写入、Git 提交/推送、DNS 修改或发布。后续 Sol 根据用户启动该阶段时的授权执行，已明确授权的步骤不重复询问。

## 2. 本轮已核实的仓库事实

1. `src/config/dynamicConfig.ts` 的 `memos.enable` 为 false。现有开关会忽略本地动态来源，不适合本方案，应保持关闭。
2. `src/utils/memos-adapter.ts` 面向浏览器直连，当前请求 `/api/v1/memos`；本方案不直接复用其作为服务端同步器。
3. 现有动态位于 `src/content/dynamic/*.md`，图片常用 `./images/*.avif`，对应 `src/content/dynamic/images/`。
4. `src/pages/api/dynamic.json.ts` 从 Astro 内容集合生成动态数据，本地图片经过 Astro 解析，并生成 WebP 预览。因此同步文件后仍需构建和发布才能上线。
5. `admin/server/content.ts` 支持 dynamic 内容，评论路径依据稳定 slug 生成。后续需追踪 `admin/shared/identity.ts` 和前台实际评论调用，不能只假设文件名就是最终 ID。
6. 后台媒体库另有私有/公开对象与分发流程，不能把它与历史动态的仓库图片路径混为一谈。默认沿用仓库动态图片流程；如果现有后台发布实现必须采用外链媒体，先呈现差异再确定，不擅自切换。

实施前按需读取：根 AGENTS.md、`.agents/skills/publish-dynamic/SKILL.md` 及 `references/images.md`、构建与架构参考中的相关部分、现有发布执行器。技能中的人工校对不应变成自动润色；同步必须保留正文，仅转换必要的附件地址。

## 3. 推荐结构

```text
手机/电脑上的原版 Memos
  ├─ 私有数据库、附件原件、编辑记录
  └─ 指定账号明确公开的动态
       ↓ 服务端同步器（凭据只保留在服务端）
       ↓ 校验、图片处理、固定身份映射、生成候选差异
       ↓ 独立发布工作目录中的 Markdown + images
       ↓ 既有可用的 Git / Astro / 部署流程
       → 博客动态页及现有评论
```

源记录以 Memos 为准；只有同步器拥有的导出文件可以被更新。旧动态保持原状。同步器不得在用户日常脏工作区自动提交。

Memos 保存成功、同步成功、Git 推送成功、构建成功、线上更新成功是不同状态，日志与交付必须分别记录。Memos 自带界面不保证展示博客部署结果；第一版通过同步任务状态/日志提供回执，不修改 Memos 前端来伪造“已上线”。

## 4. 同步契约

### 内容和身份

- 只接收指定实例、指定账号且明确公开、处于有效状态的主动态；排除私密、仅登录可见、归档和评论记录。准确字段以固定版本 API 为准。
- 保存持久映射：实例标识 + memo 稳定 ID → 文件路径、稳定 slug、首次发布时间、源版本/内容摘要、附件映射及最近成功发布版本。
- 文件名遵循项目时间命名规范，发生同秒冲突时稳定追加 ID；后续编辑不得改名或重建评论身份。
- 保留原文、时区语义、图片顺序。标签不擅自删除或另加；置顶、位置仅在确认原字段含义和本地 schema 兼容后映射。
- 公共仓库中不写入私密正文、凭据或内部接口信息。映射中有敏感内容的部分留在服务器私有状态目录。
- 不同步 MDX，不执行笔记内代码。对 YAML/frontmatter 边界和可执行 HTML 按现有安全渲染契约处理并测试。
- 人工修改了同步器拥有的导出文件时，用摘要识别冲突并暂停该条记录，不静默覆盖。其他历史文件完全不动。

### 图片

- 默认最终落盘 `src/content/dynamic/images/`，Markdown 使用相对图片引用，继续使用 Astro 现有资产生成及预览逻辑。
- Memos 原件保留在私有附件存储；发布副本按既有约定转高质量 AVIF，保留朝向、色彩、尺寸及可见内容，不默认裁切或缩小。
- 使用安全、不冲突的小写文件名和附件 ID/内容摘要映射，实现重复执行不重复下载或生成文件。正文图片与附件列表可能重复，不盲目追加第二份；优先保持明确的正文顺序。
- 动图、透明图片、HEIC 等按实际支持能力处理。不能安全保留内容时报告该条阻塞，不静默丢失动画或生成替代图片。
- 附件下载限制协议、来源、大小、类型、超时与重定向目标，禁止任意 URL 访问内网、路径越界或把凭据转发到其他主机。外部图片链接默认保留，不自动抓取不受信域名。
- 全部所需图片就绪后再原子生成该条候选内容；失败不发布缺图版本。删除图片不自动物理删除历史资产，后续如需清理另行处理。

### 触发、幂等与撤回

- 第一版优先使用有界定时拉取，建议约 60 秒、可配置；只有变化才生成候选和触发发布，短时间多次编辑合并处理。更新延迟是“轮询时间 + 排队 + 构建部署时间”，不是承诺一分钟上线。
- 使用固定版本支持的分页与增量查询；周期性做完整核对。使用锁防止并发任务、退避重试、持久任务状态和源版本检查，避免旧任务覆盖新版本。
- Webhook 如有需要作为后续加速，并验证该版本是否支持及其鉴权；不能只依赖事件而没有补偿核对。
- 超时、鉴权失败、分页不完整、临时列表缺失都不能当作删除依据。撤回只能依据可靠的状态查询或完整核对结果。
- 明确改为私密、归档或删除时，只撤回对应同步器拥有的公开内容，沿用既有发布链路。不把私密正文用 `draft: true` 提交到公共 Git 仓库。
- 已公开内容无法保证从 Git 历史、浏览器缓存及已分发图片中彻底消失。撤回验收针对当前网站内容和受控缓存；彻底清除历史记录不是本阶段目标。
- 原子更新图片/Markdown/映射，并持久记录候选与发布回执，保证进程重启后能够恢复；备份恢复后的状态也应可重新核对。

## 5. 分阶段执行

遵循项目习惯：每阶段独立新对话，用户要求开始下一阶段时带上前阶段证据、具体范围和授权边界。用户另有安排时遵从。

### 阶段一：确认接口、部署隔离试用实例

先只读核实服务器资源、现有容器/反代、备份位置和实际发布方式；不要把历史交接中的服务器状态当作当前事实。

- 从官方发布选择具体稳定版本并固定镜像版本/摘要。核实 API 路径、身份、分页、可见性、附件、评论、删除和导出契约；不要把 latest/main 文档当稳定版保证。
- 部署独立 Memos 与持久卷，不改现有服务。默认 SQLite，若使用 PostgreSQL 则独立数据库和受限账号。使用独立回环端口，先通过受保护入口试用；正式域名/HTTPS 在获授权后配置。
- 管理员初始化后限制注册；API 令牌与附件原件保持私有。不要用公开 API 查询来推断私密记录是否已删除。
- 验证文字、多图、编辑、可见性切换、删除、重启持久化、匿名私密访问拒绝；备份数据库、附件、配置并做一次隔离恢复。

验收产物：版本和 API 契约记录、部署配置、资源实测、备份恢复记录、下一阶段所需内部地址和凭据位置（不写秘密值）。未获部署授权时只准备配置与 dry-run，明确停在部署边界。

### 阶段二：实现同步器与本地候选生成

- 按职责拆分 API 客户端、状态映射、内容转换、图片导入和发布适配层。路径由 Sol 阅读现有代码后确定，不强制另建重复框架。
- 提供 dry-run/预览差异与正式应用模式；在隔离目录验证，不写入历史动态。
- 复用安全、已可用的后台能力；若其完整发布器仍受暂停的 MDX 构建或未解决条件阻塞，报告真实依赖。不得擅自恢复暂停项，也不得顺手建设另一套大型发布后台。
- 定向测试：公开过滤、正文和顺序、稳定身份、重复执行、分页失败、附件失败、同秒冲突、手工编辑冲突、撤回和进程重启恢复。必要时验证旧版本任务不能覆盖新状态。
- 用少量合成内容完成一次可信源码完整构建，核对 `dist/api/dynamic.json` 和生成资产、预览图、评论路径及历史内容无变化。检查新增代码的类型与相关格式，不全仓写入格式化。

验收产物：可运行同步器、配置示例、定向测试和构建证据、候选文件清单、部署/回退说明。默认不提交、不推送、不改线上。

### 阶段三：授权后接通正式发布

- 明确自动化权限：Memos 哪个账号的公开操作会触发博客 Git 提交/推送和现有部署；部署目标、撤回行为、机器人账号权限和冲突策略写入配置/文档。取得此范围授权后无需每条动态再询问。
- 使用独立受控工作目录，拒绝任务外差异，仅暂存同步器拥有的文件，采用 Conventional Commits。远端有新提交时安全更新；冲突停止，禁止强推或重置用户工作区。
- 确认发布顺序与最新源版本，防止构建期间撤回的内容又被旧任务重新上线。状态明确区分已同步、待构建、失败和已上线。
- 用用户认可的一条测试动态验证手机上传、多图顺序、编辑不丢评论身份、改私密/删除后的当前站点撤回，以及同步故障时原站正常。
- 验证实际 Git、自动部署和线上生成内容，不能用一次 API 200 代替发布完成。默认不涉及 OpenAI Sites。

验收产物：正式配置、发布回执、公开内容和图片检查、运维操作说明。失败可关闭同步任务并恢复最近成功公开版本；不删除 Memos 数据，不回滚用户无关提交。
