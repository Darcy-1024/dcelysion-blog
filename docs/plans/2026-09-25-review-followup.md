## 工作包 A：评论迁移文件一致性（优先）

所有权：`deploy/tencent/convert-twikoo.mjs`、对应测试、必要的迁移包本地校验工具及 `import-comments.sh`，以及 deploy/tencent/README.md 的相关章节。

### 问题与实现要求

转换器当前只在目标 JSON 不存在时复制源文件，但每次覆盖 SQL 和 manifest。旧、新同名输入先后转换到同一目录，会产生旧 JSON + 新 SQL。import-comments.sh 在 psql 完成提交后才 verify-import，故校验报错时导入已发生。

1. 先完成输入解析与 convert 校验，再发布输出，避免无效输入留下看似可导入的半成品。
2. 优先采用每次生成新迁移包、拒绝复用非空输出目录的简单规则；兼容已有 CLI 参数，给出明确错误。不默默覆盖旧备份，不增加危险的强制覆盖默认行为。
3. 如需要临时输出目录，使用同级唯一目录，完成全部源 JSON、SQL、manifest 后才原子发布；失败只清理由本次创建的临时文件。不能递归删除用户既有目录。
4. 给 manifest 记录输入文件与 SQL 的 SHA-256（仅摘要和文件名，不含个人数据），导入前先在本地校验包完整性。校验失败须在 backup/psql 之前退出。保留现有数据库导入后逐字段验证，以及 SQL 的事务和目标表必须为空约束。
5. 对旧格式包给出清晰行为：优先要求从原始导出重新生成，不得默认绕过校验。文档只说明新行为，不改写历史部署事实。

### 验收

- 保留原 4 个转换测试。
- 合成数据验证：新目录成功；同名新输入重用非空目录被拒绝且所有既有文件字节不变；无效输入不发布完整包；更改 JSON 或 SQL 后包预检失败；正确包预检成功。
- 测试仅用临时目录和虚构评论。若无法运行 PostgreSQL，明确未验证真实数据库导入，不运行服务器测试脚本来补足。

## 工作包 B：静态版本完整发布与失败恢复（优先）

所有权：`deploy/tencent/install-staging.sh`、纯本地测试或必要辅助脚本，以及同一 README 的部署章节。与工作包 A 由同一 Sol 负责，避免文档冲突。

### 问题与实现要求

当前 release 目录存在即跳过解包；解包中断后只要 index.html 存在，重试就可能启用残缺版本。current 和 Nginx 配置又在验证前改变，后续错误不恢复。

1. 保留压缩包 SHA-256 校验；在唯一临时目录安全解包，验证首页及该项目必要产物（Pagefind、静态入口、引用的关键资源；采用适度规则，不要求遍历远程资源）。
2. 完整版本才原子重命名到 release 路径并设置完成标记，标记包含完整包摘要。既有目录没有标记或摘要不一致时拒绝复用；不要自动删除未知目录。
3. 记录原 current 链接、将要改写的 Nginx 文件/链接与默认站状态。先准备配置并执行 nginx -t，尽量把 current 切换后移；任何已发生修改的阶段失败都恢复本次修改涉及的旧状态。
4. 保留旧 release，使用原子链接替换切换版本；reload 或健康检查失败时回退旧链接和配置，并清楚报告回退成功或失败。首次部署没有旧链接时也需合理恢复。
5. curl 增加连接/总超时，避免部署无限挂起。防止并发执行争用 current.next 和备份目录，可采用系统已有 flock 或唯一临时路径，保持依赖简单。
6. 为测试提供受控路径和命令注入点，生产默认路径/私有监听行为不变。禁止测试通过实际 sudo、systemctl、nginx 或 docker 操作宿主服务。

### 验收

- 对 Bash 做语法检查；若环境提供 Bash，用临时根目录和命令桩运行故障注入。
- 覆盖正常发布、解包失败、已有残缺 release、nginx -t 失败、reload 失败、HTTP 健康检查失败、同一包安全重跑。
- 失败时旧 current 及被改写配置保持或恢复，旧发布目录和媒体不受影响；中断残留不能被误认完整版本。
- Windows 无可用 Bash 时诚实说明限制，仍提供可复用测试；不得仅因脚本能解析就声称回滚行为通过。
