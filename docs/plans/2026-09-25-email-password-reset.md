# 邮箱验证找回密码执行方案

日期：2026-09-25。需求：访客忘记账号密码后，通过注册邮箱验证身份并设置新密码；本方案交给新对话中的 GPT-6 Sol 实现。

用户追加要求：**所有发出的邮件统一使用简体中文文案**。此要求覆盖注册确认、密码重置、评论回复/站长通知，以及服务端实际存在的其他邮件类型；不能只处理新找回邮件。

## 一、现状与范围

- 账号属于腾讯云部署的 Waline，不是文章/相册的访问密码。博客仍允许匿名评论。
- `deploy/tencent/README.md` 记录服务端为 Waline 1.41.6；`compose.yaml` 固定容器摘要，管理端固定 `@waline/admin@0.34.2`，博客客户端为 3.15.2。
- 现有管理端已经有 `/ui/forgot` 入口。已读取本地管理端缓存和 1.41.6 npm 包：`PUT /api/user/password` 向注册邮箱发信，链接为 `/ui/profile?token=...`；控制器使用 `jwt.sign(userId, jwtKey)`，未设置过期时间，格式与正常登录令牌一致。不能把它当作已经具有限时、单次消费能力的重置凭证。
- 历史文档记录过注册确认、找回邮件送达及令牌读取资料，但没有完成修改密码后的完整登录验收。历史记录不是本次实测结果。
- SMTP 已有配置路径，数据库为 PostgreSQL；优先复用这些基础设施。域名当前仍属私有预览，不能把公网访问失败误判为功能错误。

目标流程：登录页 → 忘记密码 → 输入注册邮箱 → 收取中文验证邮件 → 点击限时链接 → 输入新密码及确认密码 → 保存成功 → 返回登录页使用新密码登录。

采用邮件链接验证。用户未要求数字验证码；链接可直接满足邮箱验证需求，并减少输码步骤。

## 二、技术路线与首轮核实

1. 先从实际固定版本核对登录、找回、资料修改、鉴权中间件、OAuth（如启用）及 2FA 路径，记录接口和令牌规则。当前官方文档用于辅助，不能替代 1.41.6 的源码。
2. 优先用 Waline 可维护的扩展机制接入重置模块；扩展不足时，使用固定基础镜像与仓库内受控源码补丁构建自定义镜像。先验证补丁应用与构建可重复，禁止直接改运行中容器或下载后的压缩 admin.js。
3. 不引入第二套用户数据库、账户体系或独立邮件供应商。密码更新必须调用 Waline 既有哈希方法，保留用户 ID、角色、邮箱、资料与评论关联。
4. 在评论服务同源下提供独立的找回和重置页面，建议 `/ui/forgot` 与 `/ui/reset-password`。前者替换现有找回表单，后者不经过普通登录守卫。静态页面/脚本以源码和构建或安装脚本维护。
5. 原 `PUT /api/user/password` 必须转入安全重置流程，或明确禁用并迁移全部调用入口。不能留着旧接口继续签发无限期普通登录令牌。

若查明同版本已有可复用的等效安全能力，可缩小实现；必须以源码和测试说明等效性，不能仅给原表单加文字后交付。

## 三、页面与接口契约

### 1. 请求重置

- 登录页清楚显示“忘记密码”，保留显示密码、注册入口及个人网站选填提示。
- 输入框使用邮箱类型和可访问标签；提交期间禁用重复提交，显示发送状态和重试提示。
- 建议新增 `POST /api/password-reset/request`，JSON 输入 `{ email, lang }`；实际路径可按 Waline 扩展能力调整，但必须保持契约一致并记录。
- 有效格式的邮箱，无论不存在、未验证、被禁用或可重置，均返回相同状态和通用文案：“如果该邮箱对应可找回的账号，我们会发送重置邮件。请检查收件箱和垃圾邮件。”
- 邮箱标准化沿用现有账号匹配规则；不要擅自去掉 Gmail 点号或加号别名，不回传账号资料。
- 对不存在账号不发送邮件；对未验证账号、禁用账号不借重置绕过账号状态。2FA 已启用时，重置密码后继续保留 2FA。

### 2. 邮件与链接

- 盘点固定版本全部发信调用、通知服务与模板，在服务端邮件生成层统一使用 `zh-CN`，不受请求 `lang`、浏览器或管理端 UI 语言影响；界面仍保留既有多语言能力。现有 Nginx 仅强制注册 POST 的语言，覆盖不完整，不足以满足本要求。
- 统一中文邮件标题、按钮、模板正文、自动生成的字段标签、页脚和提示；保留用户评论原文、昵称、站点名、代码和链接，不翻译用户内容。缺失的中文模板补齐，避免回退英文；不静默吞掉缺失模板错误。
- 对注册确认、找回密码、访客回复、站长通知及盘点出的其他发信类型，分别在本地邮件接收器/模板测试验收；至少以 `en` 和 `zh-CN` 请求验证自动生成文案均为中文。不得为此向真实评论用户群发测试邮件。
- 中文标题建议“[DcElysion] 重置密码”；正文包含操作按钮、15 分钟有效期、非本人操作可忽略，以及站点署名。
- 链接 origin 由可信服务端配置生成，不信任请求 Host、任意 returnUrl 或用户提供的跳转地址。
- 建议 `/ui/reset-password#token=<随机凭证>`，避免原始凭证进入常规访问日志；页面读取后立即清除地址中的凭证，仅在内存中保留。
- 页面不加载第三方统计，设置 `Referrer-Policy: no-referrer` 与 `Cache-Control: no-store`。只有提交新密码才消费凭证，邮件扫描器和预览 GET 不改变密码。
- 私有预览使用隔离环境自己的回调地址与邮件接收器。不可修改生产 SERVER_URL 来迁就本机隧道；真实公网链接可达性需在相应部署阶段单独验收。

### 3. 提交新密码

- 两次输入新密码，显示/隐藏可切换，允许粘贴和密码管理器，使用 `autocomplete=new-password`。
- 建议 `POST /api/password-reset/confirm`，JSON 输入 `{ token, password }`。确认密码仅用于前端一致性检查；密码规则由前后端共同执行。
- 新密码采用至少 12 个字符、允许长密码和 Unicode、不过度要求字符组合的规则；具体最大长度须核对现有哈希实现的字节限制，禁止静默截断。若受既有机制限制，明确显示实际规则并保持服务端一致。
- 成功后清除重置凭证和当前账号本地登录缓存，显示“密码已更新，请重新登录”，跳回普通登录入口，不通过重置链接直接建立普通会话。
- 失效、已使用、伪造凭证统一显示“链接已失效，请重新申请”；密码不一致、密码不合规则、网络错误、429 分别提示可执行的下一步。服务端失败不得显示成功。
- Waline 通常使用 `{ errno, errmsg, data }`，前端要同时判断 HTTP 状态和业务状态。

## 四、服务端安全与数据一致性

### 重置凭证

- 用加密安全随机源产生至少 32 字节随机值，数据库只存 SHA-256 摘要，不存明文凭证或密码。
- 增加独立重置表，建议字段：ID、用户 ID、凭证摘要（唯一）、创建时间、过期时间、消费时间；按用户和过期时间建立必要索引。
- 有效期 15 分钟，每个用户只保留最新一次有效申请。重发、消费和并发提交通过事务/锁或等效原子机制处理，不靠前端按钮保证一次性。
- 提交新密码时，在同一数据库事务内：锁定并验证凭证、再次校验用户状态、更新密码哈希、撤销该用户重置凭证、更新该用户会话版本。并发重放只允许一笔成功；任一步失败则整体回滚。
- 原始凭证不能被普通登录、个人资料、评论管理等接口当作 bearer token 使用。

### 会话与旧链接

- 需要支持“密码重置后撤销该用户已有会话”。建议账号增加会话版本字段，新会话携带并核对版本；重置时原子递增。
- 对旧版无版本令牌制定兼容规则，例如只在该用户仍为初始版本时接受；重置过的用户拒绝无版本令牌。核对所有令牌签发入口，避免漏掉 OAuth 或管理员登录。
- 旧找回链接与旧登录令牌格式相同，不能声称能够单独识别旧找回链接。新流程停止签发旧令牌；某账号完成重置后，该账号旧版登录及找回令牌一起失效。
- 不通过轮换全站 JWT 密钥实现单用户找回，以免导致无关用户被迫退出。已有管理员角色及 2FA 配置保持不变。

### 防滥用与故障

- 保留 Nginx 现有认证请求限流；为新接口补齐限流匹配。默认建议同邮箱 60 秒冷却、每小时最多 5 次请求；IP 限额沿用现有每分钟 6 次并结合实际页面请求检查误伤。
- 邮箱维度计数使用标准化邮箱摘要，所有有效格式邮箱一视同仁，不能通过限流响应判断账号是否存在。前端倒计时只是交互，实际限制在服务端执行。
- 发信耗时和错误不能直接暴露账号存在性；使用现有可靠异步机制或一个有界、可观察的发信处理方案，避免引入无限队列。SMTP 失败记录脱敏错误，用户可重试，失败申请不应留下可被误报已送达的状态。
- 日志不记录请求体、明文凭证、密码、SMTP 密钥或完整邮件链接；错误页不输出这些数据。
- 过期记录清理有边界、可重复，不能影响用户和评论数据。

最低验收矩阵：

| 场景 | 必须证明 |
| --- | --- |
| 正常找回 | 邮件到达测试接收器，链接打开，修改成功，新密码登录成功，旧密码失败 |
