## 4. 主页预测速行为规范

### 4.1 探针契约

- 两端部署相同公开小文件，建议固定版本路径 `/__route/probe-v1.bin`，大小 32 KiB、内容和 SHA-256 一致；样本由构建/打包脚本生成，不使用私有媒体、不下载整页或音视频测速。
- 主页只请求受代码配置控制的两个 HTTPS origin。使用 GET、`credentials: omit`、`redirect: error`、`cache: no-store`、AbortController；不使用 `no-cors` 的 opaque 响应充当成功证据。
- 计时从请求前开始，到完整读取规定字节结束；内容校验在计时之外。拒绝非 200、错误 MIME、超长/短缺内容、错误摘要及重定向。读取设字节上限，即使 Content-Length 缺失也能受控校验。
- 两家对探针设置一致缓存/压缩策略。可让 CDN 缓存固定探针，但避免浏览器本地缓存；不随意添加随机 query 打穿 CDN。不声称冷启动与热缓存差异已被完全消除。
- 探针响应允许主页的实际 Origin 跨域读取；开发 Origin 仅在本地配置允许。固定无凭据公开探针若采用 `Access-Control-Allow-Origin: *`，仅限定在这个端点；不扩展到 API/私有内容。需要读取额外头时配置 expose headers；只有使用 Resource Timing 明细时才依赖 TAO，计时默认使用 performance.now。
- CSP 的 connect-src 和平台响应头在两端按需适配，不能假定两家都支持同一 `_headers` 文件。探针不能落入 SPA HTML 回退、登录校验或 Bot challenge。
- 探针只代表小文件当前请求质量，不是带宽测试或完整站点可用性证明。

### 4.2 一轮决策与降级

以下为实现初值，可通过有证据的验证调整，不机械照搬媒体路由配置：

| 参数 | 初值 |
| --- | --- |
| 默认线路 | Cloudflare |
| 同一轮总超时 | 2500ms，两端各受同一截止时间约束 |
| 样本 | 每端至多 32 KiB，正常一轮约 64 KiB 响应体 |
| 切到 EdgeOne 的优势 | 完整请求耗时比 Cloudflare 至少低 20% |
| 自动测试频率 | 同一主页 origin、同一标签会话仅首次一轮 |

- 两端成功：按总耗时比较，差距不足保留默认。
- 仅一端成功：选成功端，另一端超时/失败不推翻成功结果。
- 两端失败或离线：默认链接仍可用，标记无有效测速结果，提供手动选择；不循环重试或自动跳转。
- 总超时达到时只取消仍 pending 的请求，不丢弃已验证成功的结果。不直接依赖 Promise.all 的首错行为。
- 主页挂载后非阻塞启动一次低优先级探测；不延迟可见内容、壁纸启动或既有音乐策略。入口尚隐藏期间默认不在生产启动自动测速，采用独立禁用开关；在本地测试夹具开启。用户以后恢复入口时一并打开选路开关。
- 选择结果只影响之后的博客导航，不修改主页 URL，不中断正在播放的媒体，不改变已打开的博客标签。

### 4.3 状态、点击与手动选择

- 独立存储键，如 `dcelysion.blog-route.v1`，与媒体 `dcelysion.media.route.v1` 完全分开。保存策略版本、端点配置版本、auto/manual 模式、选中线路和 pending/ready 状态。
- sessionStorage 失败时内存降级；挂载/重入去重并清理 AbortController、监听器和计时器。配置版本变化可失效旧记录；记录只接受白名单 source，不直接信任缓存 URL。
- 刷新时遇到中断 pending 记录使用默认降级，不引发刷新测速循环。手动“重新测速”才明确开启新一轮；同一时间只保留一轮。
- 浏览器的 sessionStorage 按 origin/标签隔离，不能声称根域与 home 子域、两个博客域之间天然共享结果；不为了共享而引入跨域 Cookie。
- 自动选中不覆盖用户在测速期间作出的手动选择；手动操作使旧一轮结果失效。网络变化、回到页面不自动重测。
- 将来入口启用后，锚点始终有默认 href。测速完成只更新未来点击目标；用户先点击时立即使用当前可用选择/默认，不 await 网络后再 window.open，保留 Ctrl/中键/新标签页与键盘语义。避免弹窗拦截。
- 手动控件提供“自动 / Cloudflare / EdgeOne”和“重新测速”，简短可访问文案；保持其正式隐藏状态，与博客入口统一。无需显示实现细节或测速进度大面板。
- JS 不可用时将来的入口退化为普通默认链接。当前入口继续隐藏，不能借 noscript 添加生产博客入口。
- 手动在博客两域切换可提供保持当前 pathname/search/hash 的链接；不新增全站自动重定向。若支持主页接收目标路径，只允许本站相对路径和两个白名单 origin，拒绝 `//`、任意外部 URL 与脚本协议。

## 5. 双域博客的兼容要求

1. 站内导航、文章、相册、搜索结果尽量为同 origin 相对链接；核对 Swup 重入、返回/前进、Pagefind 和资源 base，不用全局替换域名的方法修改用户正文或历史外链。
2. canonical、og:url、RSS/sitemap 的规范 URL 保留 Cloudflare 主域；此规范化不触发 HTTP 跳转。只针对程序生成链接修正，不润色用户内容。
3. 按实际依赖更新 CSP、CORS、统计允许域、评论/其他公开 API 的 Origin 白名单。R2 媒体的精确 Origin 白名单需增加实际 EdgeOne 博客 origin，并按已有媒体约定验证；不把这解释为启用腾讯媒体双来源。
4. 两域 localStorage/sessionStorage、Cookie 独立。记录阅读设置/主题等是否各自保存，不引入认证共享，不绕过后台 Access 或复制私有会话。
5. 统计仍只加载一份；评论入口保持现有隐藏。监控手动跳转可能产生正常跨域访问，不重复注入统计脚本。
6. 访客直接从搜索引擎进入某条博客线路时不经过主页测速；该线路完全不可达时无法运行页面 JS 来自救，不能承诺全站无感容灾。保留主页和另一线路的可用访问地址供用户手动打开。

## 6. 双端构建与发布

博客当前已知源码链供执行者复查：

- `wrangler.jsonc` 使用 `dist` 静态资产；`.github/workflows/deploy.yml` 是 GitHub Pages，不是 Cloudflare 发布证据。
- `admin/build/entrypoint.sh` 与完整 `pnpm build` 在联网缓存生成和 Sites wrapper 上有差异。
- `admin/server/releases.ts` 的 packageArtifact 生成 `site.tar.gz`、摘要、文件清单和 release ID。
- `admin/server/jobs.ts` 当前为构建/封包、核对候选和媒体、Git push、腾讯安装；publishing-config/shared publishing 当前是单目标部署状态。
- `deploy/tencent/admin-release.py` 原子切换腾讯 current；现有 rollback 不回退 Cloudflare/EdgeOne。

实现要求：

- 同一个公开源码快照，优先构建一次并分发两端；记录源版本/工作区快照、环境配置摘要、公开文件清单和各平台 deployment ID。平台分别构建时验证实际公开产物，不只比 Git SHA。
- 由脚本在独立打包目录筛选公开站点文件。EdgeOne 不一定识别 `.assetsignore`，显式排除音乐/视频/相册原媒体、后台/秘密/草稿输入、Sites 的 `server/index.js`；保留相册路由 HTML、字体、搜索等应用资源。不手改 dist，不删除原文件。
- 同时生成探针和不含秘密的站点版本信息。probe-v1 可跨发布保持稳定，发布版本使用单独探针，不让某次两端部署时间差导致无谓测速失败。
- 两端部署状态独立记录，失败端幂等重试，不重复 Git push/构建。当前后台单目标模型若需扩展，应和正在修改构建链的执行者划清文件所有权，不伪装成腾讯 release 成功。
- 先部署验证两端，再启用主页选路功能；当前用户保留入口隐藏，因此正式入口启用留用户后续操作。某端版本落后时不推广为自动选择目标；切换与发布窗口中的旧新 hash 资源兼容必须验证。
- 新旧版本资源保留或平台原子部署，避免用户在旧 HTML 上请求已删除资源。跨平台不存在天然原子提交，不声称无任何版本差窗口。
- 受限 MDX builder 和正式后台上线仍按最新交接推进，不因本任务绕过资源门槛；不增加用户电脑构建环境，不顺带开启后台/媒体生产功能。

## 8. 最小测试与回退
